# Contributing

Use short `codex/`, `feat/` or `fix/` branches and a focused pull request.
Run `npm ci && npm run check`. Explain the user-visible behavior, validation
and limitations. Preserve source fidelity, host ownership and the free core.

Changes to the SDK belong here first. Applications consume reviewed versions;
do not maintain a second editable copy of the core as a long-term workflow.

Before a contribution is merged, maintainers must record explicit acceptance
of [CLA.md](CLA.md) for the reviewed contribution and verify corporate authority
where applicable. Do not infer acceptance from a PR or use a DCO sign-off as a
substitute for commercial sublicensing rights. Until that process is completed,
maintainers must not merge the contribution. Any substantive revision needs
confirmation that acceptance covers the final contribution.

Retain third-party provenance. Dependencies, generated assets and license
changes need review of their actual distribution terms. Do not include tokens,
customer documents, internal business plans or application signing resources.
